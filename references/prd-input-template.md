## 3. 功能描述

### 3.1 核心功能清单

| 功能编号 | 功能描述 | 优先级 | 备注 |
|---------|---------|--------|------|
| F001 | 用户在登录页点击"忘记密码"，进入重置流程 | P0 | 入口功能 |
| F002 | 输入注册邮箱，系统发送包含重置链接的邮件 | P0 | 核心流程 |
| F003 | 点击邮件中的链接，跳转到新密码设置页 | P0 | 核心流程 |
| F004 | 输入并确认新密码，完成重置 | P0 | 核心流程 |
| F005 | 重置成功后自动登录并跳转首页 | P1 | 优化体验 |
| F006 | 重置链接 30 分钟后失效，显示重新申请入口 | P1 | 安全需求 |
| F007 | 频率限制：同一邮箱每小时最多申请 3 次 | P1 | 防滥用 |

### 3.2 功能详细描述

#### F001 - F004：完整重置流程

**Step 1：申请重置**
- 用户在登录页点击"忘记密码？"链接
- 跳转到 `/forgot-password` 页面
- 页面显示邮箱输入框和"发送重置链接"按钮

**Step 2：发送邮件**
- 用户输入注册邮箱并点击提交
- 系统验证邮箱格式
- 系统检查邮箱是否存在（若不存在，出于安全不告知用户，仍显示"已发送"）
- 发送重置邮件（含 token，有效期 30 分钟）
- 页面显示"重置邮件已发送至 xxx@xx.com，请在 30 分钟内操作"

**Step 3：设置新密码**
- 用户点击邮件中的链接，跳转到 `/reset-password?token=xxx`
- 系统验证 token 是否有效（未过期、未使用）
- 若 token 无效：显示错误提示 + "重新申请"按钮
- 若 token 有效：显示新密码设置表单

**Step 4：完成重置**
- 用户输入新密码（8-20 位，包含字母和数字）
- 用户再次输入确认密码
- 点击"确认重置"
- 系统更新密码，使 token 失效，使所有已有 session 失效
- 自动登录当前用户，跳转到首页
- 显示 Toast："密码已成功重置"

## 4. 验收标准

> 格式：Given（前提条件）/ When（操作）/ Then（预期结果）

### F001 - F004 核心流程验收

| # | Given | When | Then |
|---|-------|------|------|
| AC001 | 用户在登录页 | 点击"忘记密码？"链接 | 跳转到 /forgot-password |
| AC002 | 在 /forgot-password | 输入有效邮箱并提交 | 显示"已发送"提示，不泄露邮箱是否存在 |
| AC003 | 在 /forgot-password | 输入无效邮箱格式并提交 | 实时显示格式错误提示，不发送请求 |
| AC004 | 点击有效重置链接 | 进入 /reset-password | 显示新密码设置表单 |
| AC005 | 两次输入一致且符合规则 | 点击"确认重置" | 密码更新成功，自动登录，跳转首页 |

| AC007 | 点击已过期（>30min）的重置链接 | 进入 /reset-password | 显示"链接已失效"，提供重新申请入口 |
| AC008 | 同一邮箱 1 小时内申请 > 3 次 | 第 4 次提交 | 显示"请求过于频繁"，无法发送 |

## 5. 边界条件和异常处理

### 5.1 输入边界

| 字段 | 最小长度 | 最大长度 | 格式要求 |
|------|---------|---------|---------|
| 邮箱 | 5 字符 | 254 字符 | RFC 5321 标准格式 |
| 密码 | 8 字符 | 20 字符 | 必须包含至少 1 个字母和 1 个数字 |

### 5.2 异常场景处理

| 场景 | 触发条件 | 处理方式 | 用户提示 |
|------|---------|---------|---------|
| 网络超时 | 请求 > 10 秒无响应 | 显示重试按钮 | "网络连接超时，请重试" |
| 服务器错误 | 5xx 响应 | 显示错误提示 | "服务暂时不可用，请稍后再试" |
| token 不存在 | token 未在数据库找到 | 提示失效 | "链接无效，请重新申请" |
| token 已使用 | token used = true | 提示已使用 | "此链接已使用，如需重置请重新申请" |
| 邮件发送失败 | 邮件服务商返回错误 | 记录错误，告知用户 | "邮件发送失败，请稍后重试或联系客服" |

### 5.3 明确不做的事（此版本范围外）

- **手机号重置**：此版本仅支持邮箱，手机号重置下个版本规划
- **安全问题验证**：不引入安全问题机制
- **重置历史记录**：不记录/展示密码重置历史

## 6. 技术约束

### 6.1 性能要求

- 邮件发送 API 响应时间 < 3 秒（P99）
- 页面首次加载 LCP < 2.5 秒
- 密码重置接口响应时间 < 500ms

### 6.2 安全要求

- 重置 token 使用加密随机字符串（128 位熵），防猜测
- 重置成功后使所有已有 session 失效（防会话劫持）
- API 返回统一响应，不区分"邮箱不存在"和"已发送"（防账号枚举）
- HTTPS only，token 不在 URL 中明文存储（改用 POST body）

### 6.3 兼容性要求

- 浏览器：Chrome 100+, Firefox 100+, Safari 16+, Edge 100+
- 设备：桌面端 + 移动端（响应式，断点 768px）
- 无障碍：键盘可操作，ARIA 标签完整
